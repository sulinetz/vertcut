# AGENTS.md — правила работы с VertCut

## Перед началом каждой сессии

1. **Обязательно прочитать `PROJECT_CONTEXT.md`** — там архитектура, модули,
   поток обработки, настройки и текущий статус функций.
2. Проверить состояние: `git status`, `git log --oneline -3`, текущий тег.
3. Прогнать тесты до любых правок, чтобы знать исходное состояние.

## Тесты

```powershell
cd vertcut
.\.venv-win\Scripts\python.exe -m pytest tests -q --basetemp="$env:TEMP\vc-pytest"
```

Без `--basetemp` на Windows pytest может падать на `PermissionError` при
уборке временных папок — это не провал логики.

- Эталон: **432 passed, 4 skipped**. Новые правки не должны уменьшать число
  проходящих тестов.
- Новую логику сопровождать тестом в `tests/`. Для таймингов, опций,
  ffmpeg-команды и схемы настроек тесты обязательны.
- Перед коммитом прогнать весь набор, а не только новый файл.

## Запуск приложения

```powershell
cd vertcut
.\.venv-win\Scripts\python.exe desktop\main.py
```

Только сервер: `.\.venv-win\Scripts\python.exe -m vertcut --port 8765`.
Данные лежат в `%APPDATA%\VertCut`, код — в `vertcut\`.

## Архитектурные правила

### Не ломать API и совместимость

- Не переименовывать и не удалять существующие HTTP-роуты, поля запросов и
  ключи настроек без миграции. Старые проекты в базе должны открываться и
  рендериться после обновления.
- Новые настройки добавлять **во все точки**:
  1. `pipeline.DEFAULT_OPTIONS`;
  2. `pipeline.normalize_options` (валидация и clamp);
  3. оба словаря `clip_settings` в `pipeline.py`;
  4. список ключей в `pipeline.rerender_clip`;
  5. `live._settings`, если настройка нужна для эфиров;
  6. поля `ClipEdit` и валидацию в `main._clean_clip_edit`;
  7. `composition.SPEC` — тип, границы, слой, подпись и подсказка. Оттуда
     границы берут проект, редактор и интерфейс (`/api/composition/schema`,
     атрибут `data-schema`).
- Новые настройки по умолчанию — выключены/нейтральны. Старый проект без
  нового ключа обязан рендериться как раньше.
- Границы одной настройки не должны задаваться в двух местах: источник —
  `composition.SPEC`.
- Не менять сигнатуры `render_clip` и `build_ass` позиционными аргументами:
  только новые keyword-параметры с значениями по умолчанию.

### Тайминги и длительность

- Любая операция, меняющая длительность (склейки, скорость), обязана
  пересчитать **и слова, и траекторию кропа, и длительность** через
  `vertcut/timeline.py`. Нельзя менять только видео.
- `timeline.py` — чистые функции без ffmpeg и диска; покрывать изменения
  юнит-тестами.
- Склейки работают только при наличии таймингов слов. Не выдумывать
  тайминги для режима «просто порезать».

### ffmpeg

- Не хардкодить частоту дискретизации: брать `utils.probe(...)["sample_rate"]`.
- Новые входы нумеровать динамически (источник → фон → музыка), не угадывать
  индексы.
- В итоговой команде сохранять `-map_metadata -1` и `-map_chapters -1`.
- Откат с аппаратного энкодера должен заменять ровно добавленный блок
  аргументов, а не срезать хвост команды.
- Граф проверять реальным рендером короткого фрагмента, а не только тестом.

### Данные и файлы

- `%APPDATA%\VertCut` — пользовательские данные: не коммитить, не удалять
  без явной просьбы.
- `assets/adhd_bg/` — пользовательские фоновые видео: не коммитить
  большие файлы.
- Не добавлять в репозиторий модели, `.venv-win`, `data/`, временные
  диагностические скрипты.

### Интерфейс

- Файлы `web/*.js`, `web/*.css` содержат кириллицу. Править их скриптами
  Python с UTF-8 и проверками (`once()`), а не через консольные heredoc —
  иначе кодировка ломается.
- После правки `app.js` или `styles.css` **обязательно** поднять версию в
  `web/index.html` (`app.js?v=N`, `styles.css?v=N`), иначе WebView отдаст
  старый код из кэша.
- Все новые настройки — с подсказкой на русском: что делает и чем грозит.
- После изменений проверять `node --check web/app.js`.

### Git

- Коммит после зелёных тестов и реальной проверки функции.
- Крупные вехи помечать тегом `v0.x.0` (теги `v1.x` — наследие upstream).
- Не пушить и не переписывать историю без просьбы.
- Рабочая ветка — `main` (ветка `stable` осталась на прежней точке).

## Что проверять руками после изменений рендера

1. Короткий фрагмент со склейками и скоростью: длительность совпадает с
   расчётом, звук не отстаёт, субтитры не разъезжаются.
2. Split-screen: 1080×1920, верх/низ на месте, звук только от источника.
3. Откат энкодера: с `VERTCUT_HW_ENCODE=0` и с аппаратным энкодером.
4. Интерфейс: блок настроек виден, значения сохраняются, редактор клипа
   открывается и перерендеривает.
5. Реклама: вставка удлиняет клип ровно на свою длину, звук источника стоит
   на паузе, субтитры не висят над рекламой; наложение двигается и исчезает.
6. Композиция: в редакторе видны слои, ползунки получают границы из
   `/api/composition/schema`, значение за пределами диапазона не сохраняется.
